# Selective UniFi Network for Home Assistant

Локальная модификация штатной интеграции **UniFi Network** для Home Assistant.
Она добавляет выбор клиентов, автоматическую очистку невыбранных устройств и
полный русский перевод параметров интеграции.

> [!IMPORTANT]
> Текущая версия `2026.11.0-local.1` основана на UniFi Network из Home Assistant **2026.11.0**
> и использует `aiounifi==97`.
> Каталог `custom_components/unifi` имеет тот же домен, что и штатная интеграция,
> поэтому Home Assistant загружает эту локальную версию вместо встроенной.
> Интеграция не создаёт предупреждения в Repairs после обновления Home Assistant.

## База Home Assistant 2026.11.0

Сохранены все пользовательские режимы, выбранные клиенты, управление доступом,
переключатель сетевого оборудования, очистка исключённых клиентов и русский
перевод. Существующие параметры подключения, идентификаторы сущностей и явно
выключенные пользователем сущности сохраняются при обновлении.

Включены изменения штатной интеграции 2026.11.0: единое восстановление соединения,
миграция идентификаторов сайтов UniFi Network 11, общие координаторы данных,
настройка подключения без удаления интеграции, новые сенсоры и правила Policy Engine.
Трекеры используют DeviceInfo; явно выбранные клиенты получают включённый по
умолчанию трекер. Это не включает существующие сущности, выключенные пользователем.

Очистка клиентов выполняется при доступном списке оборудования и затрагивает
только сущности этой записи интеграции. Общие устройства других интеграций
сохраняются. Изменение списка клиентов для блокировки также перезагружает запись,
чтобы восстановить отсутствующих клиентов и убрать исключённые устройства.

Перед заменой файлов сохраните резервную копию. После обновления выполните
`ha core check` и перезапустите Core: вместе с кодом обновляется зависимость aiounifi.

## Возможности

- три режима клиентов: все, только выбранные или ни одного;
- отдельный выбор клиентов для управления доступом;
- автоматическое удаление сущностей и устройств невыбранных клиентов;
- отдельное включение сетевого оборудования UniFi;
- русские названия и пояснения параметров;
- понятный переключатель **Блокировка доступа**:
  - включён — клиент заблокирован;
  - выключен — доступ к сети разрешён;
- отсутствие повторяющегося предупреждения об обновлении локальной интеграции
  после обновления Home Assistant.

## Установка

### Вариант 1: архив релиза

1. Скачайте архив нужной версии из раздела Releases.
2. Распакуйте каталог `unifi` в:

   ```text
   /config/custom_components/unifi
   ```

3. Проверьте, что итоговый путь к манифесту выглядит так:

   ```text
   /config/custom_components/unifi/manifest.json
   ```

4. Выполните проверку конфигурации и перезапустите Home Assistant:

   ```bash
   ha core check
   ha core restart
   ```

Каталог можно загрузить через Samba, SSH, Studio Code Server или File editor.

### Вариант 2: из Git

На компьютере с доступом к конфигурации Home Assistant:

```bash
git clone https://github.com/akinin/home-assistant-unifi-selective.git
mkdir -p /config/custom_components/unifi
cp -R home-assistant-unifi-selective/unifi/. /config/custom_components/unifi/
```

После копирования выполните `ha core check` и перезапустите Core.

## Настройка

Откройте:

```text
Настройки → Устройства и службы → UniFi Network → Настроить
```

Основные параметры:

- **Все клиенты** — поведение штатной интеграции;
- **Только выбранные** — сущности создаются только для отмеченных клиентов;
- **Не добавлять клиентов** — клиентские устройства не создаются;
- **Сетевое оборудование UniFi** — шлюзы, коммутаторы и точки доступа;
- **Клиенты с управлением доступом** — создаёт переключатель блокировки.

Клиент, выбранный для управления доступом, сохраняется в Home Assistant даже
при режиме «Не добавлять клиентов», поскольку его переключатель должен оставаться
доступным.

## Обновление модификации

1. Сделайте резервную копию каталога `/config/custom_components/unifi`.
2. Замените его содержимое файлами новой версии.
3. Не переносите старые `__pycache__` и файлы macOS вида `._*`.
4. Выполните:

   ```bash
   ha core check
   ha core restart
   ```

Параметры подключения и выбранные клиенты хранятся в config entry Home Assistant,
поэтому обычная замена файлов интеграции их не удаляет.

## Обновление Home Assistant

После обновления Home Assistant интеграция продолжает загружаться без отдельного
предупреждения в Repairs. Рекомендуется:

1. проверить журнал на ошибки `custom_components.unifi`;
2. при появлении ошибок обновить файлы интеграции и перезапустить Core.

## Откат к штатной интеграции

Штатные файлы Home Assistant не изменяются. Для отката:

1. удалите только каталог:

   ```text
   /config/custom_components/unifi
   ```

2. перезапустите Home Assistant.

После перезапуска снова загрузится встроенная интеграция UniFi Network. Перед
откатом рекомендуется сохранить резервную копию конфигурации.

## Проверка после установки

- в журнале Home Assistant нет ошибок `custom_components.unifi`;
- в манифесте отображается ожидаемая локальная версия;
- выбранные клиенты присутствуют в реестре;
- невыбранные клиенты удалены;
- для переключателя «Блокировка доступа» включённое состояние действительно
  соответствует блокировке в контроллере UniFi.

## Тесты

Для локальных тестов нужен Python 3.14.2 или новее:

```bash
uv venv --python 3.14
uv pip install -r requirements-test.txt
.venv/bin/pytest -q
```

Тесты используют изолированный Home Assistant и контроллер с подставленными
ответами API. Они проверяют режимы клиентов, управление доступом, трекеры,
переключатель оборудования, сохранение общих устройств и обновление опций.

## Примечание о поддержке

Это локальная модификация встроенного компонента Home Assistant, а не отдельная
интеграция с новым доменом. Изменения штатной UniFi Network в новых версиях Core
необходимо переносить в этот проект вручную.

Исходный компонент взят из проекта
[Home Assistant Core](https://github.com/home-assistant/core/tree/2026.11.0/homeassistant/components/unifi).
При распространении необходимо соблюдать условия лицензии Home Assistant Core.
