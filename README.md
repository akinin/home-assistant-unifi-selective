# Selective UniFi Network for Home Assistant

Локальная модификация штатной интеграции **UniFi Network** для Home Assistant.
Она добавляет выбор клиентов, автоматическую очистку невыбранных устройств и
полный русский перевод параметров интеграции.

> [!IMPORTANT]
> Версия **2.0.0** — тонкий адаптер к встроенной UniFi, а не копия её реализации.
> Он использует `homeassistant.components.unifi` из установленного Home Assistant.
> Проверенная начальная версия Core: **2026.11.0**. Зависимости берутся из текущего
> встроенного manifest; собственной закреплённой версии `aiounifi` нет.

## Как работает адаптер

Соединение с контроллером, протокол API, координаторы, WebSocket, платформы,
классы сущностей, discovery, reauth и reconfigure остаются во встроенной UniFi.
При обновлении Core этот код обновляется вместе с Home Assistant. В репозитории
нет копий `hub/`, `coordinator.py`, `entity.py` и реализации сенсоров.

Адаптер добавляет политику выбора до создания сущностей, безопасную очистку,
настройки, стандарт включения выбранных трекеров и смысл блокирующего переключателя.
Общий фильтр охватывает и отдельный discovery-путь сенсоров. Явно выключенные
пользователем сущности не включаются принудительно.

Платформы делегируют вызовы текущим модулям `homeassistant.components.unifi.*`.
Тексты, иконки и описания служб создаются из ресурсов установленного Core с
небольшими JSON-наложениями. Русские подписи сохранены; новые поля Core наследуются.
Генерируемый UI-кэш не является отдельной копией Python-интеграции.

## Совместимость и обновления

Используются внутренние точки расширения UniFi, которые не являются стабильным
публичным API. Ручное слияние всей интеграции больше не требуется. При изменении
этих точек может понадобиться обновление небольшого адаптера.

Перед запуском проверяются сигнатуры, поля конфигурации, платформы, классификация
сущностей и смысл блокирующего переключателя. При обнаруженной несовместимости
загрузка останавливается до подключения к контроллеру и создания сущностей;
в Repairs появляется понятное сообщение. Автоматического запуска без фильтра нет.

GitHub Actions запускает регрессионные тесты при push/PR, вручную и ежедневно в
07:23 МСК. Проверяются базовая HA 2026.11.0 и последняя стабильная версия из PyPI,
с соответствующим Python и нативными зависимостями UniFi. Тесты не имеют доступа
к настоящему контроллеру и не обновляют сервер автоматически.

Основная среда установки — Home Assistant OS / Container: официальный образ
содержит зависимости встроенных интеграций. Для отдельной установки Core через
pip сначала установите нативные зависимости командой из раздела тестов.

## Возможности

- три режима клиентов: все, только выбранные или ни одного;
- отдельный выбор клиентов для управления доступом;
- автоматическое удаление сущностей и устройств невыбранных клиентов;
- отдельное включение сетевого оборудования UniFi;
- русские названия и пояснения параметров;
- понятный переключатель **Блокировка доступа**:
  - включён — клиент заблокирован;
  - выключен — доступ к сети разрешён;
- отсутствие повторяющегося предупреждения об обновлении локальной интеграции
  после обновления Home Assistant.

## Установка

### Вариант 1: архив релиза

1. Используйте архив адаптера 2.x, собранный `scripts/build_adapter.py`.
   Старые Releases 2026.8.x содержат прежнюю полную копию интеграции.
2. Распакуйте каталог `unifi` в:

   ```text
   /config/custom_components/unifi
   ```

3. Проверьте, что итоговый путь к манифесту выглядит так:

   ```text
   /config/custom_components/unifi/manifest.json
   ```

4. Выполните проверку конфигурации и перезапустите Home Assistant:

   ```bash
   ha core check
   ha core restart
   ```

Каталог можно загрузить через Samba, SSH, Studio Code Server или File editor.

### Вариант 2: из Git

На компьютере с доступом к конфигурации Home Assistant:

```bash
git clone https://github.com/akinin/home-assistant-unifi-selective.git
mkdir -p /config/custom_components/unifi
cp -R home-assistant-unifi-selective/unifi/. /config/custom_components/unifi/
```

При переходе с прежней полной копии сохраните старый каталог за пределами
`custom_components` и замените его целиком: старые `hub/`, `entity.py` и
`coordinator.py` оставаться не должны. Параметры config entry сохраняются.
После копирования выполните `ha core check` и перезапустите Core.

## Настройка

Откройте:

```text
Настройки → Устройства и службы → UniFi Network → Настроить
```

Основные параметры:

- **Все клиенты** — поведение штатной интеграции;
- **Только выбранные** — сущности создаются только для отмеченных клиентов;
- **Не добавлять клиентов** — клиентские устройства не создаются;
- **Сетевое оборудование UniFi** — шлюзы, коммутаторы и точки доступа;
- **Клиенты с управлением доступом** — создаёт переключатель блокировки.

Клиент, выбранный для управления доступом, сохраняется в Home Assistant даже
при режиме «Не добавлять клиентов», поскольку его переключатель должен оставаться
доступным.

## Обновление модификации

1. Сделайте резервную копию каталога `/config/custom_components/unifi`.
2. Замените его содержимое файлами новой версии.
3. Не переносите старые `__pycache__` и файлы macOS вида `._*`.
4. Выполните:

   ```bash
   ha core check
   ha core restart
   ```

Параметры подключения и выбранные клиенты хранятся в config entry Home Assistant,
поэтому обычная замена файлов интеграции их не удаляет.

## Обновление Home Assistant

После обновления Home Assistant интеграция продолжает загружаться без отдельного
предупреждения в Repairs. Рекомендуется:

1. проверить журнал на ошибки `custom_components.unifi`;
2. при появлении ошибок обновить файлы интеграции и перезапустить Core.

## Откат к штатной интеграции

Штатные файлы Home Assistant не изменяются. Для отката:

1. удалите только каталог:

   ```text
   /config/custom_components/unifi
   ```

2. перезапустите Home Assistant.

После перезапуска снова загрузится встроенная интеграция UniFi Network. Перед
откатом рекомендуется сохранить резервную копию конфигурации.

## Проверка после установки

- в журнале Home Assistant нет ошибок `custom_components.unifi`;
- в манифесте отображается ожидаемая локальная версия;
- выбранные клиенты присутствуют в реестре;
- невыбранные клиенты удалены;
- для переключателя «Блокировка доступа» включённое состояние действительно
  соответствует блокировке в контроллере UniFi.

## Тесты и сборка

Нужен Python версии, подходящей целевому Home Assistant (для 2026.11.0 — 3.14.2+):

```bash
uv venv --python 3.14
.venv/bin/python scripts/install_test_dependencies.py --ha-version 2026.11.0
.venv/bin/python -m pytest -q
.venv/bin/python scripts/build_adapter.py --output dist/unifi-adapter-2.0.0.tar.gz
```

Скрипт берёт версии `aiounifi` и discovery из текущих встроенных manifest.
Архив содержит адаптер и UI-ресурсы целевой версии Core. При каждом старте UI-кэш
обновляется из установленного Core; исходные файлы HA не изменяются.

Тесты проверяют режимы клиентов, фильтрацию всех платформ, управление доступом,
сохранение пользовательских отключений, очистку общих устройств, обновление опций,
реальное использование нативных классов и остановку при изменении контрактов.

## Примечание о поддержке

Каталог `unifi/` имеет тот же домен, что встроенная интеграция. Это позволяет
установить фильтр до запуска нативной записи, сохранив существующие параметры,
ID и автоматизации. Отдельная интеграция, которая выключает сущности после их
создания, не обеспечивает такую же семантику и здесь не используется.

Адаптер следует текущему коду [Home Assistant Core](https://github.com/home-assistant/core/tree/2026.11.0/homeassistant/components/unifi).
При откате обязательно восстанавливайте целиком предыдущий каталог, а не смешивайте
его файлы с адаптером. Резервные копии настроек и реестров содержат личные данные
и должны оставаться на сервере.
