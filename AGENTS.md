# UniFi Selective — тонкий адаптер

## Архитектура

- Версия адаптера: `2.0.0`. Проверенная базовая HA: `2026.11.0`.
- `unifi/` устанавливается в `/config/custom_components/unifi` с прежним доменом.
- Python-код встроенной UniFi не копируется. Протокол, Hub, координаторы, WebSocket,
  классы сущностей и connection flows берутся из `homeassistant.components.unifi.*`.
- Не возвращай каталоги `hub/`, копии `entity.py`, `coordinator.py`, API и сенсоров.
  Файлы платформ содержат только делегирование нативным функциям.
- `adapter_bootstrap.py` читает manifest именно встроенной интеграции через
  `Integration.resolve_from_root`. Не вызывай для него `async_get_component()`:
  кэш HA использует домен и может вернуть сам адаптер. Импортируй native модули
  по полному имени. Зависимости устанавливаются из текущего native manifest;
  не закрепляй собственную версию `aiounifi`.
- Основная среда — HA OS/Container, образ которого содержит native requirements.
  Для pip-окружений используй `scripts/install_test_dependencies.py` до запуска.
- `adapter_metadata.py` объединяет текущие native strings/translations/icons с
  небольшими `overlays/`. Генерируемые UI-ресурсы не являются fork Python-кода.
  При регенерации дождись предыдущего кэша переводов, затем используй публичные
  `async_invalidate_translations` и `async_load_integrations`.
- Сохраняй `translations/.gitkeep` и seed `services.yaml`: HA замечает эти ресурсы
  ещё до загрузки компонента. Архив сборки включает актуальный UI-кэш.

## Инварианты доработок

- Режимы клиентов: all/selected/none; отдельные client_source и block_client.
  Клиенты управления доступом сохраняются в none. Старые track_* настройки мигрируют.
- Фильтры выполняются ДО создания сущностей в общем loader И отдельном sensor discovery.
  Простое отключение сущностей после создания не заменяет эту семантику.
- Фильтр сетевого оборудования охватывает физические устройства/порты/розетки;
  служебные сущности контроллера и WLAN сохраняют отдельную классификацию.
- Блокировка: включён = заблокирован. Согласованно изменяются control/state/events/icons.
- Явно выбранный новый tracker включён по умолчанию. Существующий user disabled_by
  нельзя сбрасывать. Сохраняй unique ID, entity ID, русские подписи и описания выбора.
- Сохраняй нативное восстановление клиентов с 30-дневной ретенцией и исключениями
  выбранных/управляемых клиентов. Не удаляй записи из-за ошибки загрузки inventory.
- Удаляй только собственные записи устройств через config-entry-scoped lookup.
  Не удаляй composite ID или чужие записи. Не возвращай remove_config_entry_id.
- При смене режима, клиентов, блокировки или оборудования нужна полная reload.
  До выгрузки дождись удаления живых запрещённых сущностей. Удаляй также старые
  trackers без device_id. Сигнал без ожидания оставляет restored/unavailable записи.
- Хуки устанавливаются один раз, с точным обратимым сохранением descriptors.
  `adapter_contracts.py` проверяет структуры, сигнатуры и семантику ДО установки.
  При несовместимости останови setup и создай Repairs issue; нельзя запускать
  нативную интеграцию без фильтров как автоматический fallback.
- Не возвращай постоянное предупреждение local_override_outdated. Issue о реальной
  несовместимости — отдельный случай, он удаляется после успешной проверки.

## Тестирование и автоматические проверки

```bash
uv venv --python 3.14
.venv/bin/python scripts/install_test_dependencies.py --ha-version 2026.11.0
.venv/bin/python -m pytest -q
.venv/bin/python scripts/build_adapter.py --output dist/unifi-adapter-2.0.0.tar.gz
```

- Тесты используют чистую официальную HA. Никогда не заменяй native пакет копией
  адаптера или прежнего fork: это делает проверки делегирования недостоверными.
- Сохраняй прежние сценарии и проверки идентичности native классов, fail-closed,
  новых полей/языков Core, идемпотентности, настроек и безопасной очистки.
- CI проверяет baseline и latest stable из PyPI: push/PR/manual и ежедневно.
  Версии Python/pytest helper/aiounifi следуют выбранному Core. Сервер CI не обновляет.
- Каждое неизвестное падение расследуй. Не считай его ожидаемым лишь ради зелёного CI.
- Проверь Python/JSON/YAML, git diff --check и Ruff в стиле соответствующего Core.

## Репозиторий и сервер

- Не коммить конфиги контроллера, списки MAC пользователя, токены, пароли, .storage,
  журналы с секретами и резервные копии. Обычный push, без force и смены global Git.
- SSH `ha_olshaniki` ведёт в Terminal & SSH, а не host/Core. Docker/Python не предполагаются.
  homeassistant_api=false; не извлекай .storage/auth и не расширяй права для обхода.
  Для UI используй существующую авторизованную панель https://ha.olshaniki.com.
- До установки сравни server source, сохрани приватный backup кода и реестров,
  параметры, ID и disabled_by. Заменяй папку целиком, не смешивай с прежним fork.
- Передавай архив проверенного коммита с checksum. Сохраняй старую папку для отката.
  Выполни ha core check и перезапуск Core; проверь fresh logs, UI, реальные показания,
  выбранные клиенты, ID/disabled_by и использование native backend.
- Не меняй работающий .storage вручную, не переключай блокировки/ISP/PoE/питание ради теста.
- Запрос на диагностику — чтение; при разрешённом исправлении доводи работу до проверки
  без повторных ритуалов подтверждения. В отчёте укажи версию, коммит, CI и серверные проверки.
