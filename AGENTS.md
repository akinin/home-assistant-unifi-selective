# Selective UniFi Network

## Назначение и база

Это полная локальная модификация встроенной интеграции Home Assistant с тем же доменом `unifi`. Каталог репозитория `unifi/` устанавливается в `/config/custom_components/unifi`; он заменяет встроенный компонент, поэтому обновление Core не обновляет эту копию автоматически.

Текущая база — Home Assistant **2026.11.0**, версия модификации — **2026.11.0-local.1**, зависимость — **aiounifi==97**. При следующем переносе сверяй обе официальные версии и реальный сервер, а не заменяй лишь номер зависимости. Обновляй согласованно `manifest.json`, README, тестовые зависимости и переводы.

## Поведение, которое необходимо сохранять

- Три режима клиентов: `all`, `selected`, `none`. Список `client_source` и отдельный список `block_client` имеют разный смысл. Клиент для управления доступом сохраняется и в режиме `none`.
- Явно выбранные клиенты обходят обычные ограничения трекера по проводному подключению, SSID и локальному MAC. Сохраняй существующую семантику глобальных флагов статистики; не обещай сенсоры при выключенных флагах без проверки `supported_fn`.
- Фильтр оборудования `create_network_entities` покрывает физические устройства, порты, розетки, трекеры и новые типы сенсоров. Служебные сущности контроллера и WLAN имеют отдельную классификацию.
- Общая проверка `UnifiEntityLoader.is_entity_allowed()` должна применяться ко всем путям создания сущностей. У сенсоров есть отдельный discovery-путь `_async_should_add_sensor`; фильтровать только `_should_add_entity()` недостаточно.
- Переключатель **Блокировка доступа**: **включён = клиент заблокирован**. Сохраняй одновременно смысл запроса `ClientBlockRequest`, событий включения, свойства состояния и иконок `icons.json`.
- Трекеры должны предоставлять `DeviceInfo`. Новые трекеры явно выбранных клиентов включены по умолчанию; существующие сущности с пользовательским `disabled_by` нельзя включать принудительно. Сохраняй ID и имена сущностей при переносе базы.
- Сохраняй 30-дневное восстановление недавно виденных неактивных клиентов. Выбранные клиенты и клиенты управления доступом восстанавливаются независимо от возраста. Отсутствие клиента из-за неудачного запроса не является основанием для массового удаления.
- Очистка исключённых клиентов должна работать только по подтверждённым клиентским MAC и при доступном inventory оборудования. Не принимай неизвестное MAC-устройство или временно недоступное оборудование за исключённого клиента.
- В HA 2026.11 используй записи устройств, принадлежащие конкретной config entry: `async_entries_for_config_entry` и `async_get_device_by_connection(..., entry_id)`. Удаляй только запись этой интеграции; не удаляй общий composite ID или записи других интеграций. Не возвращай устаревший `remove_config_entry_id`.
- Старый трекер без `device_id` тоже должен удаляться при очистке устаревших клиентов, даже если отдельная запись устройства с этим MAC существует.
- Изменение режима, выбранных клиентов, списка управления блокировкой или переключателя оборудования требует полной перезагрузки записи. Перед выгрузкой дождись удаления живых сущностей, запрещённых новыми опциями; один dispatcher-сигнал без ожидания оставляет `unavailable/restored` записи.
- Сохраняй совместимость старых настроек `track_clients`/`track_devices`, подписи клиентов с IP/SSID/MAC и выбранные отсутствующие клиенты в форме.
- Сохраняй русский перевод и совпадение ключей `translations/ru.json` с `strings.json`. Не возвращай удалённое предупреждение Repairs `local_override_outdated`.

## Проверки

Нужен Python **3.14.2+**. Тесты не обращаются к настоящему контроллеру и не переключают реальные устройства.

```bash
uv venv --python 3.14
uv pip install -r requirements-test.txt
.venv/bin/pytest -q
```

На текущей базе проходят **22 регрессионных теста**. При изменении поведения добавляй проверку наблюдаемого результата: сущностей, реестра, запроса управления или применения опций. Не подменяй проверку поведения утверждениями, повторяющими реализацию.

Проверяй синтаксис, JSON, `git diff --check` и Ruff в стиле соответствующей версии Home Assistant. Для базы 2026.11.0 используется Ruff `0.17.3`; при наличии checkout Core применяй его `pyproject.toml` как конфигурацию, чтобы не переформатировать официальный код по другим правилам импорта.

При переносе базы полезны официальные тесты UniFi. Отличия формы опций и инверсии блокировки ожидаемы, но каждое другое падение нужно объяснить; не помечай неизвестную ошибку ожидаемой только ради зелёного результата.

## Работа с репозиторием и сервером

- Запрос только на диагностику не разрешает замену серверных файлов. При явном запросе исправления доводи разрешённые изменения до проверенного результата без повторных ритуалов подтверждения.
- Не коммить настройки контроллера, MAC-списки пользователя, пароли, токены, журналы с секретами, `.storage` и резервные копии. Не меняй глобальную Git-конфигурацию. Используй обычный push, без принудительной перезаписи ветки.
- Для сервера пользователя используется SSH alias `ha_olshaniki`. Это дополнение Terminal & SSH; не предполагается доступ к Docker или Python контейнера Core.
- У SSH-дополнения нет `homeassistant_api`. Не извлекай данные сессий из `.storage/auth` и не расширяй права дополнения для обхода ограничения. Пользуйся разрешённым API или существующей авторизованной панелью HA.
- Перед установкой сравни серверные исходники с репозиторием, учти серверные правки, сохрани приватную резервную копию кода и затрагиваемых реестров. Зафиксируй параметры, ID сущностей и `disabled_by`.
- Передавай архив конкретного проверенного коммита, исключая `__pycache__`, `*.pyc` и `._*`; сверяй контрольные суммы. Сохраняй предыдущую папку для отката. Не редактируй работающие `.storage` вручную.
- Выполняй `ha core check` перед запуском. Для новой базы и зависимости перезапускай Core. После запуска проверяй реальную версию, статус интеграции, живые датчики, выбранные клиенты, ID и пользовательские отключения, а также свежую часть журнала.
- Для проверки не переключай реальные блокировки клиентов, ISP, PoE и питание сетевого оборудования. Проверяй команды в тестах, а на сервере читай состояние.

Отчёт должен содержать версию, ссылку на коммит, результат применения на сервере, выполненные проверки и существенные ограничения. Не заявляй полную совместимость лишь на основании успешного импорта.
